# 보스 생산 분해: 자료 확보 결과와 다음 추정 설계

작성일: 2026-09-12. 분석 종점: 2026-08-21. 현재 작업은 자료 확보·검증 및 설계이며 새 분해 모형의 적합 완료를 의미하지 않는다.

## 목표와 고정 범위

기존 총생산/보스 생산 정본 PNG를 새로 그리거나 재추정하지 않는다. 우선 전체 보스 생산 B를 본섭과 챌린저스의 생산으로 분리한다.

`B_t = A_t * bM_t + C_t * bC_t`

본섭은 계정 내 여러 보스 캐릭터를 포함한 계정 평균, 챌린저스는 사용자 지정대로 1인 1주력 생산 캐릭터로 모델링한다. 사냥·주화·칼럼·전체 유효인구 지표의 재설계는 이번 적합의 목적에서 제외한다. 사냥이나 주화가 스펙과 완전히 무관하다는 가정까지 추가하는 것은 아니다.

## 1. 원시 파일 복구: 완료

`Maple/data/raw/meso_total_production_raw_canonical.part00.b64`에서 base64 문자 하나가 누락돼 있었다. 0-based offset 5997에 `H`를 삽입한 경우에만 기존에 기록된 SHA-256과 일치하는 압축 해제 결과가 나왔다. 숫자 fitting이나 재디지타이징을 하지 않았다.

- 원래 문서의 SHA-256: `63e41f7c7d5c384971524a56df0dcc01a25fd888f808e9174b3195feb9dd6b41`
- 복구 JSON: `Maple/data/meso_total_production_raw_canonical.json`, 61,198 bytes.
- 기존 `restore_meso_total_raw.py`가 이제 정상 실행되고 위 SHA를 검증한다.
- JSON에는 **총생산 1,664 좌표만** 있다. 보스 고해상도 배열은 없다.
- JSON의 `source_data`는 `meso_total_boss_share_data.json`을 가리킨다. 이 파일은 현재 탐색에서 찾지 못했다.
- 보스 생산은 기존 주간 입력 패널의 direct/backcast 열로 접근 가능하다. 이를 고해상도 원시 보스 배열을 찾았다고 표현하지 않는다.

검색 범위: 현재 저장소와 Git 이력, 접근 가능한 사용자 Downloads/Desktop/Documents/Temp 파일명 검색. 파일명으로 찾지 못한 보스 원본의 존재 자체를 부정하지 않는다.

### 기존 CSV와의 관계: 중요한 정정

`month = (year-2023)*12 + month_number-1 + (day-1)/days_in_month`에서 원시 총생산을 선형보간하면 기존 주간 `P_total_newage100`와 141행 전체가 거의 일치한다. 최대 절대 차이 0.00007132845, 평균 절대 차이 0.00000306368.

따라서 과거 대화의 **서로 전혀 다른 원자료라는 단정은 철회**한다. 기존 열 이름과 단위, 패치일과 국소 극값 날짜의 혼동을 분리해서 봐야 한다. raw 값에 문서의 6.495250069를 곱하면 마지막 값은 1183.6974로 PNG의 1183.7과 일치한다.

6개 표시값은 실제 패치 날짜에 강제로 놓지 않는다. 곡선의 평탄한 저점/고점 구간에서는 특정 대표 날짜를 정하는 규칙이 필요하다. 이미지 복원 좌표의 분수 날짜는 시각 측정 정밀도를 의미하지 않는다. 새 그래프는 아직 변경하지 않았다.

## 3. 자료 확보 후 권고하는 추정 순서

### A. 관측 기간과 모집단 확정

- 날짜를 점이 아니라 집계 시작/종료 구간으로 기록한다. 목요일 인구 라벨은 앞 주 활동을 요약할 수 있다.
- 공식 곡선의 끝 2026-08-21까지만 사용한다. 새로운 8/21 보스 실측을 만들어내지 않는다.
- 시즌 오픈일 C=0과 실제 시즌 외 C=0을 구분한다. 마지막 관측을 다음 주로 무조건 연장하지 않는다.
- 기존 B의 direct/backcast 구간을 분리하고 후자의 관측오차를 더 넓게 둔다. 숫자 좌표 부족을 이유로 PNG를 다시 추정하지 않는다.

### B. 본섭·챌섭 평균 생산량을 동시에 추정

관측식은 `B_obs = A*bM + C*bC + observation_error`. 여기의 A/C는 먼저 집계 정의를 맞춘 활동계정이며 사용자의 챌섭 1인1캐릭 가정을 적용한다. log 생산성의 낮은 자유도 추세와 근거 있는 보상 변화만 먼저 사용한다.

- 비챌섭은 bM의 강한 관측 구간이지만 리프 직후와 계측 정의 변경 주는 깨끗한 대조군으로 자동 지정하지 않는다.
- 챌섭은 시즌 경과·해방 가능 시점·규칙별 차이를 반영한다. 시즌별 성장 속도와 수준을 같게 강제하지 않는다.
- 결정석 조정은 본섭과 챌섭의 보스 구성이 다르므로 집단별 가중효과를 계산하거나 불확실성으로 남긴다.
- bM 경로를 확정하고 잔차를 무조건 bC로 보내지 않는다. late bC를 V2에서 가져와 고정하지 않는다.
- 본섭 신규 유입은 실제 코호트가 없으므로 우선 짧은 시차 반응으로만 비교한다. A_eff와 incumbent productivity를 동시에 자유롭게 추정해 비식별성을 키우지 않는다.

### C. 시즌2·3 달성 정본을 추정에 결합

시즌2·3 표의 수치를 정본 입력으로 사용한다. 각 시즌의 달성 경로를 성장 상태와 연결하고, 본섭/챌섭 총량 항등식 및 인구 관측과 함께 적합한다. 누적 달성자와 현재 활동계정 사이의 리프·활동 차이는 모형의 별도 상태에서 처리하며 정본 숫자를 수정하지 않는다. 시즌4의 개별 게시글 자료는 별도 출처 검증을 유지한다.

티어별 보상은 총량의 상대지수와 단위를 맞춰야 한다. 티어 조건상 보스 접근 가능성이 주간 실제 판매를 보장하지 않으므로 참여율·파티 배분·판매 제한을 구분한다.

### D. 작은 후보군과 통과 기준

1. 최소 공동분해(추세 + 외생 보상 변화).
2. 위 모형 + 본섭 유입의 단기 시차 반응.
3. 위 모형 + 집계 정의가 맞는 성장자료 제약.

일부 기간을 통째로 가리는 예측 검사, 서로 다른 잠재 분해를 가진 가상자료 복원 검사, 달성자료 제외/포함 검사, 인구 제공자·날짜 정렬·late drift 민감도를 수행한다. B 총량만 맞고 bM/bC가 회복되지 않으면 분해를 식별했다고 보고하지 않는다. V3는 비교 기준으로 보존한다.

다음 적합의 산출물은 `date, bM, bC, B_main, B_challenger, challenger_boss_share, uncertainty, source_quality`이며 모든 유효 행에서 잠재 총량 `B_main+B_challenger=B`를 검사한다. 관측오차와 모형 가정 범위는 분리한다. 처음부터 하나의 1인당 총생산선으로 합치지 않는다.
